# Field transforms, step 3: the elastix importer

**Status:** Implemented (2026-10-13; plan and implementation reviewed by Codex gpt-6-sol)
**Last updated:** 2026-10-13
**Scope:** `xarrayrf.elastix`, which reads elastix parameter maps and files into core
transforms, and one core change it needs: a declared upper support edge on
`BSplineTransform`. The third of the five steps of stage 1a in the
[field transform design](field_transform_design.md) (step table in the
[step 1 plan](field_transform_step1_plan.md)), under the
[transform adapter](../adapters/transform_adapters_design.md) contract.

## Context

Pirana's `pirana.registration.elastix` has `transform_from_map` and `transform_from_maps`:
translation, Euler (with `ComputeZYX` and centre), affine (with centre) and cubic B-spline
stages, 3-D only, with LPS/RAS conversion folded into boundary affines. It needs no ITK
runtime. The design moves it here as code, adapted to frame endpoints.

**transformix, measured** with itk-elastix 0.25.4 (ITK 5.4.7) on axis-aligned control grids, in
2-D and 3-D, for both `BSplineTransform` and `RecursiveBSplineTransform`:

- The B-spline displaces points on control index `[1, n − 2)`: lower face included, upper face
  excluded. ITK's own `BSplineTransform` (step 1) includes the upper face. Outside, transformix
  returns the point unchanged.
- On an oblique control grid a point computed to lie on a face lands on either side by
  roundoff, as in ITK (step 1).
- `RecursiveBSplineTransform` takes its support from `GridIndex` but evaluates its values as if
  `GridIndex` were zero; with a zero index it equals `BSplineTransform` exactly. elastix writes
  zero indices, so only a zero index is imported for it.

The fixture `tests/fixtures/elastix_transforms.json` is generated by
`tools/build_elastix_fixture.py` (dry run by default, `--apply` writes) from hand-built maps:
transformix deformation fields over an oblique output grid, and face probes. Cases: rigid then
B-spline (3-D, oblique grid with a nonzero `GridIndex`); Euler with `ComputeZYX`, then affine,
then translation (3-D, non-commuting); a `RecursiveBSplineTransform`; Euler then B-spline
(2-D); affine (2-D). Each case also records the parameter files as elastix writes them, the
later stages naming the earlier file in `InitialTransformParameterFileName`.

## Current Decision

### Core change: `BSplineTransform(..., support="closed")`

`support` declares the upper support edge: `"closed"` (`[1, n − 2]`, ITK's, the default) or
`"half-open"` (`[1, n − 2)`, elastix's). It changes only the classification of points on the
upper face, the `"raise"` message's bracket and the repr (shown when not the default); the
`"nearest"` clamp and the polynomial are unchanged. It is kept through pickling. Any other value
raises `ValueError`. The design already says support is declared per producer; this is the
B-spline's declaration.

### Public API (`xarrayrf.elastix`)

No extra is needed: the module uses only NumPy and the core.

```python
from xarrayrf import elastix as rfe

maps = rfe.read_parameter_files("out/TransformParameters.1.txt")  # initial stage first
imported = rfe.transform_from_parameter_maps(maps, fixed=fixed, moving=moving)
imported.transform  # fixed -> moving; resamples the moving image onto the fixed grid
imported.report  # ((code, message), ...)
```

- `read_parameter_file(path) -> dict[str, tuple[str, ...]]` parses one elastix text file:
  `(Key value ...)` entries, values as strings with quotes removed, `//` comments outside quotes
  ignored. Anything else, a repeated key, or an unterminated entry raises `ValueError` with the
  line number.
- `read_parameter_files(path) -> tuple[dict, ...]` follows `InitialTransformParameterFileName`
  from the given (last) stage back to `NoInitialTransform` and returns the stages in application
  order. A relative name is resolved against the referring file's directory, as elastix writes
  it next to the file. A missing file raises `FileNotFoundError` naming the referring file; a
  cycle raises `ValueError`.
- `transform_from_parameter_maps(maps, *, fixed, moving, space=None, intermediate_frames=None)
  -> ElastixImport`:
  - `maps`: parameter maps in application order (`Mapping[str, Sequence[str]]`, as itk-elastix
    returns them), or an object with `GetNumberOfParameterMaps()` and `GetParameterMap(i)` (an
    itk-elastix `ParameterObject`), read in index order. Empty input is refused. The first map
    must have no initial transform (`InitialTransformParameterFileName` absent or
    `NoInitialTransform`); otherwise the chain is incomplete and the import refuses, pointing to
    `read_parameter_files`. Later maps' references are ignored, since the order is given.
  - `fixed`, `moving`: the caller's `ReferenceFrame`s; they must not be the same frame
    (`is_equivalent_frame`), as the adapter contract requires.
  - `space`: the `CoordinateSystem` elastix's physical points were expressed in. Default for
    three dimensions: the LPS patient system in millimetres (`patient_coordinate_system(LPS,
    "mm")`), since ITK reads medical images into LPS. Other dimensions require it.
  - The stages map between `fixed.with_coordinate_system(space)`, one fresh
    `ReferenceFrame.local(space)` per internal boundary (or the caller's `intermediate_frames`,
    one per boundary, each with coordinate system `space`), and
    `moving.with_coordinate_system(space)`. Where `fixed` or `moving` is expressed in another
    system, `coordinate_system_change` joins it at that end, and its errors propagate (an
    unoriented frame needs an explicit `space`; units are never rescaled).
  - The result is `compose(...)` of the members: one `AffineTransform` when every member is
    affine, else a `CompositeTransform` that keeps each stage.
  - `ElastixImport` is a frozen dataclass of `transform` and `report`.

### Stages

The dimension is `FixedImageDimension`, which must equal `MovingImageDimension` and
`len(space.axes)`. Every stage must have `HowToCombineTransforms` `Compose` (the default when
absent) and `UseDirectionCosines` `true` (the default when absent); `NumberOfParameters`, when
present, must equal the number of `TransformParameters`. Every value must parse as a finite
number where a number is expected. Violations raise `ValueError` naming the stage and key.
Stage `k` maps the output of stage `k − 1`; elastix's `Compose` applies the initial transform
first.

| `Transform` | Parameters | Result |
|---|---|---|
| `TranslationTransform` | `t` (D) | `y = x + t` |
| `EulerTransform` (D = 2) | `θ, t` | `y = R(θ)(x − c) + c + t` |
| `EulerTransform` (D = 3) | `θx, θy, θz, t`; `ComputeZYX` | `R = Rz Ry Rx` if `ComputeZYX` is `true`, else `Rz Rx Ry` |
| `AffineTransform` | `A` (D², row-major), `t` | `y = A(x − c) + c + t` |
| `BSplineTransform`, `RecursiveBSplineTransform` | coefficients | `BSplineTransform(..., outside="identity", support="half-open")` |

`c` is `CenterOfRotationPoint` (required for Euler and affine). B-spline stages need
`BSplineTransformSplineOrder` 3 (other orders raise `NotImplementedError`, since the core
implements cubic only) and `UseCyclicTransform` `false`. Their control grid is
`GridOrigin + GridDirection · diag(GridSpacing) · index` for index `GridIndex ..
GridIndex + GridSize − 1`, with `GridDirection` column-major; the core grid has dims and
`ArrayCoordinates` axes `i, j, k` (then `l`, ... beyond three), unit coordinates `0 .. n − 1` and
the index offset folded into the translation. A `RecursiveBSplineTransform` with a nonzero
`GridIndex` raises `NotImplementedError` (see Context). `TransformParameters` are component-major, each
component's grid with the first index fastest, and become coefficients shaped `(*GridSize,
D)`. Any other `Transform` raises `NotImplementedError` naming the supported ones.

### Report

One entry per normalization, `(code, message)`:

- `stage`: one per stage, naming its elastix transform and the frames it maps between.
- `coordinate-system-change`: one per end where the caller's frame is converted to or from
  `space`.
- `bspline-support`: once when a B-spline stage is present: elastix's half-open support and
  identity outside are declared on the transform.

### Tests (`tests/test_elastix.py`)

- Every fixture case: the imported chain maps the fixture's points to transformix's within
  `1e-5` mm (transformix writes float32 displacements), from the maps and from the parameter
  files written to `tmp_path` and read back through `read_parameter_files`.
- Face probes test the B-spline stage alone (the generator evaluates only the last map): off-face
  probes agree; on-face probes agree except where roundoff decides, which the test checks by
  recomputing the probe's continuous index through the control grid.
- A synthetic aligned grid: a point exactly on the upper face is the identity, exactly on the
  lower face is displaced (`support="half-open"`), and the same coefficients with
  `support="closed"` displace both (core test in `test_field_transforms.py`).
- RAS caller frames: the chain starts and ends with the coordinate change, and maps like the
  LPS chain with signs flipped; all-affine chains collapse to one `AffineTransform`.
- 2-D without `space` is refused; an unoriented 3-D frame without `space` gets
  `coordinate_system_change`'s error; same fixed and moving frame refused.
- Each refusal: a first map with an initial transform, a recursive B-spline with a nonzero
  `GridIndex`, unsupported transform, spline order, cyclic, `Add` combination, direction
  cosines off, parameter count mismatch, non-finite value, missing centre, dimension mismatch,
  bad `ComputeZYX`, wrong number of intermediate frames or their coordinate system.
- Parser: comments, quoted strings with spaces and `//`, repeated key, garbage line,
  unterminated entry; chain following with relative names, a missing file, a cycle.
- `ParameterObject`-like input (a stub with the two methods).

## Alternatives Considered

| Alternative | Why not |
|---|---|
| Treat the upper-face difference as negligible, as Pirana does | Elastix places its control grid relative to the fixed image, so a whole image face can sit on the upper support face; the difference is then a face of voxels, not a measure-zero set |
| Fold coordinate changes into boundary affines (Pirana) | `compose` collapses all-affine chains already; in mixed chains a separate member is explicit and costs one matrix product |
| An `xarrayrf[elastix]` extra | Nothing to install |
| Inferring `space` from the frames | Identity and conventions are never inferred; LPS is the stated default for 3-D because ITK reads medical images into LPS |
| Accepting `fixed == moving` for motion correction | The adapter contract refuses it: give the moving image a new local frame |
| `SimilarityTransform`, `AffineDTITransform`, stack and kernel transforms now | No consumer yet; refused with a clear message |
